# Reverse Engineering Analysis — fusan.com.tw

**Target:** `http://www.fusan.com.tw/chinese/`
**Date:** 17 Nov 2026
**Scope:** Reverse-engineer the existing site, then rebuild it with proper i18n/l10n and a modern front end.
**Deliverable:** `Desktop/fusan-modern/` — working proof of concept in zh-TW / en-US / ja-JP.

---

## 1. Reverse engineering: what the current site is

### 1.1 Provenance

The page carries its own build fingerprint in an HTML comment:

```html
<!-- Fireworks 4.0  Dreamweaver 4.0 target.  Created Fri Aug 31 11:22:35 GMT+0800 2001 -->
```

The site was generated by **Macromedia Fireworks 4 + Dreamweaver 4 in August 2001** and has been patched by hand ever since. Doctype is `HTML 4.01 Transitional`.

### 1.2 Architecture

| Aspect | Finding |
|---|---|
| Layout engine | Nested `<table>` slices — up to **9 levels deep**, fixed `width="760"` |
| Content delivery | Layout is a sliced Fireworks JPEG grid (`index_01.jpg` … `index_33.jpg`) |
| Navigation | **Text baked into GIF images**, swapped on hover by `MM_swapImage()` |
| Styling | `<font size>` / `<font color>` tags, inline `bgcolor`, one small `main.css` |
| Scripting | Dreamweaver `MM_*` helpers; `MM_reloadPage()` reloads the page on Netscape 4 resize |
| Backend | Classic ASP (`news.asp`, `product_01.asp?p_c_id=1..6`) |
| Encoding | **Big5** (`charset=big5`) on sub-pages; the homepage declares UTF-8 but is served inconsistently |
| Templating | FrontPage/Dreamweaver templates (`<!-- #BeginTemplate "/Templates/main.dwt" -->`) |

### 1.3 Site map recovered

```
/chinese/
├── index.html              homepage
├── company/company_all.htm 公司簡介 — profile, milestones, equipment, certs
├── product/product.htm     產品介紹

```

### 1.4 Content extracted

Decoding the Big5 pages yielded the real content, which I carried into the rebuild:

- **Company:** founded 5 Apr 1962, chairman 鐘連在, Changhua plant 30,000 m², 350 staff, 2M units/month
- **Four global sites:** Changhua HQ, Taiwan sales (富鋼), Dongtai China plant, Shanghai sales
- **10 milestones:** 1962 founding → 1975 CNS → 1979 AGA → 1981 CSA → 1989 UL/ASSE → 1995 ISO 9002 → 2000 NSF/BSMI/CMA → 2003 Suzhou
- **12 certifications:** UL, CNS, CSA, CGA, AGA, ASSE, IAPMO, ANSI/NSF, FM, CMA, ISO 9001, PED/CE
- **6 product families** with real model numbers: F1361FP, F1361SPMCL, F1221F, F1151S, F1331SRF, F1173E
- **Corporate values:** 富山四維「精、誠、勤、和」
- **5-stage process:** material inspection → casting/forging → 100% inspection → machining → pressure test

## 2. i18n/l10n findings on the original

### 2.1 How "localization" works today

The site has **two hand-maintained parallel copies**: `/chinese/` and `/english/`. No shared source, no message catalog, no tooling.

| Problem | Evidence | Consequence |
|---|---|---|
| **Duplicated sites** | `/chinese/` and `/english/` are separate file trees | Every copy edit must be made twice; they have already drifted |
| **English site is stale** | `/english/index.htm` lacks the 富山閥門介紹 and catalogue-download blocks present in Chinese | Foreign buyers see less information than domestic ones |
| **No Japanese at all** | Only zh + en exist | Japan is named in the company's own copy as a key export market |
| **Text locked inside images** | `index_16.gif` = 基本資料, `index_19.gif` = 產品介紹 | A new language requires a **graphic designer**, not a translator. Text is unsearchable, unselectable, unzoomable, invisible to Google |
| **Big5 encoding** | `charset=big5` on all sub-pages | Cannot represent Japanese kana or any non-CJK script. Mojibake on modern defaults |
| **No `lang` attribute** | `<html>` with no `lang` | Screen readers use the wrong voice; browsers pick the wrong font and line-breaking rules |
| **No `hreflang`** | absent | Google cannot connect the language variants; they compete in search |
| **Language switch is an image** | `index_26.gif` "English Version" | Not keyboard-discoverable, no `lang` attribute on the link |
| **Hard-coded date formats** | ASP pages emit `YYYY/MM/DD` | Wrong for US (`MM/DD/YYYY`) readers; ambiguous for everyone |
| **No locale persistence** | Switching language forgets on next visit | Repeat visitors re-switch every time |

### 2.2 Accessibility and modernization gaps

- Most navigation images carry **no `alt`** → screen readers announce nothing
- Fixed `width="760"` → **unusable on mobile**, no viewport meta tag
- Text in images **cannot reflow or scale**
- Blue underlined `#0000FF` links on a patterned background — poor contrast
- `MM_reloadPage()` targets Netscape 4 and fires on every resize
- Catalogue offered as **`.rar`**, which macOS and most phones cannot open
- No HTTPS

## 3. Recommended i18n architecture

### 3.1 Principles applied in the rebuild

| Principle | Implementation |
|---|---|
| **Externalize every string** | All UI text lives in `locales/*.js`; no English or Chinese prose in the HTML/JS logic |
| **Key by ID, never by source text** | `nav.products`, not `"產品介紹"`. Copy edits in one language never orphan the others |
| **Separate stable data from translatable data** | `data.js` holds model numbers, sizes, phone numbers, years. Catalogs hold only prose |
| **Never concatenate sentences** | Full sentences with `{placeholder}` interpolation; word order differs per language |
| **Real pluralization** | `Intl.PluralRules`, not `n === 1 ? a : b` |
| **Format, never hard-code** | `Intl.NumberFormat` / `DateTimeFormat` / `RelativeTimeFormat` / `ListFormat` |
| **Graceful degradation** | Missing keys fall back to en-US and warn in the console; never blank UI |
| **Locale is a document-level concern** | Sets `<html lang>`, `dir`, font stack, `og:locale` |
| **Brand marks are not prose** | Logos and glyphs (精/誠/勤/和) live in `data.js` and stay identical in every locale — see §4.6 |
| **Design for text expansion** | Fixed-size containers are sized for the longest locale, not the source; verified by stress test — see §4.6 |
| **Locales can override formatting conventions** | A catalog may supply its own list separator when `Intl` picks the wrong one — see §4.7 |

### 3.2 Locale negotiation chain

```
?lang= URL param  →  localStorage  →  navigator.languages  →  en-US fallback
```

The URL parameter comes first so links are shareable, testable, and crawlable.

### 3.3 Why text-in-images had to go

This was the single biggest blocker. Replacing six navigation GIFs with real text means:

- Adding Japanese is a **translation task, not a design task**
- Nav text is indexable by Google in all three languages
- Screen readers announce it; users can zoom and select it
- It reflows on mobile

## 4. Localization details handled

### 4.1 Typography per locale (`styles.css`)

```css
html[data-locale="zh-TW"] { --font: Inter, 'Noto Sans TC', …; --lh-body: 1.85; }
html[data-locale="ja-JP"] { --font: Inter, 'Noto Sans JP', …; --lh-body: 1.9; }
```

CJK needs **looser line-height** than Latin (1.85–1.9 vs 1.6) and no negative letter-spacing. Latin webfonts contain no CJK glyphs, so a per-locale stack is required.

```css
html[data-locale="zh-TW"] body { line-break: strict; word-break: normal; }
```

CJK has no inter-word spaces, so browsers may break mid-phrase. `line-break: strict` applies kinsoku rules (no line starting with 。 or 」).

```css
html[data-locale="zh-TW"] .kicker { text-transform: none; letter-spacing: .05em; }
```

`text-transform: uppercase` with wide tracking is a **Latin** typographic device. It does nothing useful to CJK glyphs and visually damages them.

### 4.2 Measurement units

`formatArea()` converts m² → ft² for en-US only. A US buyer reading "80,000 m²" has no intuition for the scale; "861,112 ft²" lands correctly.

| Locale | Rendered |
|---|---|
| zh-TW | `80,000 m²` |
| en-US | `861,112 ft²` |
| ja-JP | `80,000 m²` |

### 4.3 Pluralization — verified live

| count | en-US | zh-TW | ja-JP |
|---|---|---|---|
| 0 | 0 product families | 共 0 個產品系列 | 全0シリーズ |
| 1 | **1 product family** | 共 1 個產品系列 | 全1シリーズ |
| 2 | 2 product families | 共 2 個產品系列 | 全2シリーズ |
| 6 | 6 product families | 共 6 個產品系列 | 全6シリーズ |

English switches form at 1; CJK has a single `other` category. A `n === 1` ternary would appear to work for these three locales and then break on the first Slavic or Arabic locale added.

### 4.4 Dates, years and relative time

| | zh-TW | en-US | ja-JP |
|---|---|---|---|
| Date | 2026年11月14日 | November 14, 2026 | 2026年11月14日 |
| Year | 1962年 | 1962 | 1962年 |
| Relative | 4 天前 | 4 days ago | 4 日前 |

CJK locales append the 年 marker automatically through `Intl.DateTimeFormat` — no string concatenation.

### 4.5 List formatting

`Intl.ListFormat` handles separators and conjunctions:

| Locale | Output |
|---|---|
| en-US | `F1361FP, F1362FP, and F1361FPW` |
| zh-TW | `F1361FP、F1362FP和F1361FPW` |
| ja-JP | `F1361FP、F1362FP、F1361FPW` |

Note the ideographic comma `、` and the absence of a conjunction in Japanese. Hard-coding `", "` would be wrong in both CJK locales.

This is the right tool for a list of *items* such as model numbers. It is **not** always right for fixed phrases — see §4.7 for a case where the locale has to override it.

### 4.6 Text expansion — the 富山四維 badge

The first build rendered the badge and the heading from the **same** catalog key.
In zh-TW that key held one character (精), which fit the 36 px badge exactly. In
English the same key returned `Precision` — 64 px of text in a 36 px box, which
overflowed and collided with the heading beside it.

Three separate i18n mistakes were stacked here:

1. **Text expansion ignored.** Translated strings routinely run 30–200% longer
   than CJK source. A box sized to the source locale will break.
2. **A brand mark treated as prose.** 精/誠/勤/和 *are* the 富山四維 concept.
   They are logos, not translatable copy, so they belong in `data.js`.
3. **The same string rendered twice.** The badge duplicated the heading in
   every locale, which also made screen readers announce it twice.

**Fix:** the glyph moved to `data.js` (identical in all locales, `aria-hidden`,
`lang="zh-Hant"` so CJK fonts apply even in the English page). The heading now
carries locale-appropriate wording — the four-character idioms in Chinese
(精益求精, 誠信敬業…), two-character compounds in Japanese (精緻, 誠実…), and
single words in English. The badge gained `overflow: hidden` and an explicit
CJK font stack so no future string can break the layout.

Verified by injecting a 28-character German compound
(`Qualitätssicherungsgrundsatz`): badge stays square, no collision, card does
not overflow.

### 4.7 List separators — when `Intl.ListFormat` is the wrong tool

The summary line under the values was initially joined with
`Intl.ListFormat(conjunction)`. In Chinese that produced:

> 「精益求精、誠信敬業、勤儉創新**和和**諧互助」

The conjunction for zh-TW is 和 — which is also the first character of the value
named **和**諧互助, giving a stuttering 和和. Switching to `type: 'unit'` removed
the conjunction but separated with a space instead of the ideographic comma 、
that the four-character motto convention requires.

**Fix:** each catalog declares its own style via `about.valuesListStyle`.
English uses `'conjunction'` and gets the full `Intl.ListFormat` treatment
including the Oxford comma; CJK locales declare the literal separator `'、'`.

| Locale | Result |
|---|---|
| en-US | Precision, Integrity, Diligence, and Harmony |
| zh-TW | 精益求精、誠信敬業、勤儉創新、和諧互助 |
| ja-JP | 精緻、誠実、勤勉、調和 |

The product-model list still uses `Intl.ListFormat` (`F1361FP、F1362FP和F1361FPW`),
which is correct there. The lesson is that `Intl` handles *lists of things*,
while a fixed motto is a typographic convention that the locale must be able to
override.

### 4.8 Bug found and fixed during testing

Browser testing surfaced a genuine localization bug:

```
© 2,026 富山精機廠股份有限公司
```

The copyright year was passed as a **number**, so `Intl.NumberFormat` applied thousands grouping. Years are **identifiers, not quantities**. Fixed by passing `String(year)`; the rule is now documented in `i18n.js`.

This is a classic i18n trap that also affects IDs, port numbers and version numbers.

### 4.9 RTL readiness

All directional CSS uses logical properties (`inset-inline-start`, `padding-inline-start`, `margin-inline`) rather than `left` / `right`. Adding Arabic or Hebrew would require only `dir="rtl"` in the locale table — the layout mirrors automatically.

## 5. Modernization applied

| Original (2001) | Rebuild (2026) |
|---|---|
| 9-level nested tables, fixed 760 px | CSS Grid + Flexbox, fluid `clamp()` typography |
| Sliced Fireworks JPEGs | Live text, CSS gradients, inline SVG icons |
| `<font>` tags, inline `bgcolor` | CSS custom properties, full **dark mode** |
| `MM_swapImage()` rollovers | CSS transitions, `IntersectionObserver` scroll reveals |
| No viewport meta | Mobile-first responsive, hamburger nav |
| Images as nav text | Semantic `<nav>` with real links + scroll-spy |
| No `alt`, no landmarks | Skip link, ARIA listbox switcher, full landmarks |
| Big5 | UTF-8 |
| `.rar` download | (recommend PDF) |
| Page reload to switch language | Instant client-side switch, no reload |

Also added: `prefers-reduced-motion` support, `prefers-color-scheme` detection, `hreflang` tags, Open Graph metadata, and JSON-LD `Organization` structured data.

### 6.1 How the bugs were actually found

Worth recording, because it shapes how this should be maintained:

| Bug | Found by | Would a key-coverage check have caught it? |
|---|---|---|
| Catalogs loaded before `I18n.register()` existed | Console errors on first load | No |
| `© 2,026` thousands-separated year | Reading rendered output | No |
| WCAG 2.5.3 label mismatch | Lighthouse audit | No |
| Badge overflow / collision (§4.6) | **Visual inspection of the English page** | No |
| 和和 conjunction stutter (§4.7) | Reading rendered zh-TW output | No |

Every one of these passed a "do all locales have all keys?" test. They were
only visible in rendered output, and three of the five only in one specific
locale. The implication: **CI should assert key parity, but a human or a
screenshot diff has to look at each locale**. Pseudo-localization (padding
every string to ~160% and wrapping it in brackets) in a staging build would
catch the whole expansion class automatically.

### The i18n engine API

```js
I18n.init()                           // negotiate locale, translate the document
I18n.setLocale('ja-JP')               // switch live, no reload
I18n.t('products.count', {count: 6})  // translate + interpolate + pluralize
I18n.formatNumber(2000000)            // 2,000,000
I18n.formatDate(date, {dateStyle})    // 2026年11月14日 / November 14, 2026
I18n.formatRelative(date)             // 4 天前 / 4 days ago / 4 日前
I18n.formatList(['A','B','C'])        // A、B和C / A, B, and C
I18n.formatList(items, 'unit')        // no conjunction
I18n.formatArea(80000)                // 80,000 m² / 861,112 ft²
I18n.onChange(fn)                     // re-render hook
```

Note the plural-set form used by `t()`:

```js
// locales/en-US.js          // locales/ja-JP.js
count: {                     count: { other: '全{count}シリーズ' }
  one:   '{count} family',
  other: '{count} families'
}
```

`Intl.PluralRules` selects the category, so a locale supplies only the forms its
grammar actually has.

### Translation hooks in markup

```html
<span data-i18n="nav.products">                     <!-- textContent -->
<h1 data-i18n-html="hero.title">                    <!-- innerHTML -->
<button data-i18n-attr="aria-label:a11y.toggleMenu"><!-- attributes -->
<span data-fmt-number="2000000">                    <!-- Intl.NumberFormat -->
<span data-fmt-year="1962">                         <!-- localized year -->
<span data-fmt-area="80000">                        <!-- value + unit -->
<span data-i18n-years-since="1962">                 <!-- computed + pluralized -->
```

Elements rendered from `data.js` (products, certifications, the 富山四維 badges)
carry no hooks: `app.js` builds them through `I18n.t()` and re-runs on every
locale change via `I18n.onChange()`.

## 8. Recommendations for production

### Immediate (this PoC is ready)
1. Replace the 2001 site with this structure
2. Migrate all content from Big5 to UTF-8
3. Convert the `.rar` catalogue to PDF
4. Serve over HTTPS

### Short term
5. Move catalogs from `.js` to `.json` and `fetch()` them — lets translators work without touching code, and enables lazy-loading
6. Add a translation management workflow (Crowdin, Lokalise, or a shared spreadsheet → JSON)
7. Add a CI check that every locale has the same key set as `en-US`
8. Use locale-prefixed URLs (`/zh-TW/`, `/en/`, `/ja/`) instead of `?lang=` for better SEO
9. Add a **pseudo-locale** (`en-XA`) to the staging build that pads every string to ~160% and brackets it. This makes text-expansion bugs like §4.6 fail loudly in the source language, before translation money is spent
10. Add screenshot diffing per locale to CI — §6.1 shows key-parity checks cannot catch rendering bugs

### Medium term
11. If a framework is adopted, this maps directly onto **i18next** (same key structure, same plural categories) or **FormatJS/ICU MessageFormat**
12. Add zh-CN — the company already operates Dongtai and Shanghai offices, and simplified Chinese is a different locale from zh-TW
13. Consider server-side rendering per locale so crawlers see translated HTML without executing JS

### Content gaps worth closing
14. The English site is missing content the Chinese one has — now structurally impossible, since all three render from one source
15. `news.asp` content was not migrated; it needs a CMS or a JSON feed
16. Product catalogue data should come from a database rather than being hard-coded in `data.js`

## 9. Scaling cost

Because every string is externalized and keyed, adding a fourth language is:

1. Copy `locales/en-US.js` → `locales/ko-KR.js`
2. Translate ~120 values (including `valuesListStyle`, and only the plural
   categories the language actually has)
3. Add one row to the `LOCALES` array in `i18n.js`
4. Add a font-stack rule if the script needs one
5. Open the page in that locale and look at it — §6.1 explains why this step
   cannot be skipped

**No HTML, no CSS layout, and no application logic changes.** Compare that to the original site, where a new language meant duplicating the entire file tree and commissioning new navigation graphics.

### Known constraints

Honest limits of this PoC, so nobody is surprised later:

- **Catalogs are `.js`, not `.json`.** Chosen so the demo runs from `file://`
  without a server. Production should switch to fetched JSON (rec. #5) —
  translators should never edit a file that can throw a syntax error.
- **Content is hard-coded** in `data.js` and the catalogs. Real product and
  news data needs a CMS or database behind it (rec. #15, #16).
- **Single page.** The original site's `news.asp` and per-category product
  pages were not reproduced; the routing and pagination they need are out of
  scope here.
- **`?lang=` rather than locale-prefixed paths.** Fine for a PoC, weaker for
  SEO than `/ja/` (rec. #8).
- **Translations are mine, not a native reviewer's.** The zh-TW copy derives
  from the company's own source text, but the en-US and ja-JP copy should be
  reviewed by a native speaker before it goes live — particularly the
  certification names, which are legal/technical terms.
